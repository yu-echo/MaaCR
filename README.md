## 这是什么

把一套自写的 OpenCV + adb 皇室战争挂机脚本，**重构到 [MaaFramework](https://github.com/MaaXYZ/MaaFramework) 之下**。

换掉的是「胶水层」，不是「识别能力」：设备层（446 行的 adb 封装）与自写 GUI 整块删除，
交给 MaaFramework 的 `AdbController` 和 [MFAAvalonia](https://github.com/MaaXYZ/MFAAvalonia)；
而模板图、量化读法、出牌策略原样保留。

**收益**：白拿 MFAAvalonia 的图形界面、多实例、定时执行、热键；流程变成声明式 JSON，
可以用 MaaDebugger / VSCode 插件可视化调试；识别结果与失败截图自动落盘。

> 这是个人自用工具，只针对**国服（腾讯代理版）**和 **MuMu 模拟器 720×1280 竖屏**调过。
> 别的分辨率、别的模拟器、别的服，没试过，也不保证。

## ⚠️ 先说清楚定位

> **它的目标是「快速刷完尽可能多的对局」**（刷宝箱 / 刷对局时长 / 刷卡牌大师进度），
> **不是上分**。所以「输」是设计的一部分，不是 bug。
>
> 当前策略是「强攻一路 + 另一边直接摆烂」——一路猛推保证至少一冠，另一边完全不守，
> 对面顺着空档很快推到三冠，而三冠会**立刻结束对局**（不用拖满 3 分钟），
> 单位时间能刷的局数接近翻倍。
>
> ⇒ **评估它好不好用，看的是「每局对战耗时」**（日志里会打），不是胜率。
>
> 反过来想让它赢：现在这套打法赢不了。必须加「场上敌方单位识别」
> （红血条 = 敌方、蓝血条 = 我方）做成「有敌人先防守、防住再反推」——
> 那是比现在大一个量级的活，见「路线图」。

## 功能介绍

### 对战

- 自动把游戏调到前台并**等到它真的就位**再开始（冷启动十几秒不会误判）
- 自动进局、按优先级与圣水条件出牌、结算后自动确认并进下一局
- 破塔后落点自动切到敌方半场深位，往国王塔压（拿三冠的关键两步）
- 局数与时间双安全阀，到数就停

### 日常

- **商店礼包**（界面里叫「领商店礼包」）：只领价格写着「免费」的卡 —— 判据是那两个**字**
  （白字掩码匹配），不是颜色，免费项不一定是绿卡。翻到「每日精选」那一屏就做判断：
  有免费项就领、没有就收工 —— **不再往下翻几十屏**
- **部落捐赠**：只捐**亮绿色**的可捐请求，灰的（自己发起的）跳过；点一下就直接捐出，
  没有二次确认弹窗，底部的「确定」只在全部捐完之后点一次（那是退出聊天的按钮）
- 启动、商店、对战、部落、退出都是**各自独立的任务**，串起来就是界面上的「**日常一条龙**」预设

### 自愈（认不出来的界面）

- ① 底部导航条还在 → 点「对战」回主界面（子页面卡住的正解，代价最低）
- ② 没有导航条 → 当全屏弹层处理（开宝箱那种多阶段动画），严格限次
- ③ 认不出来 **且画面也定格了**够久 → 判定真卡住，重启游戏（最贵但最确定）
- ⚠️ **绝不按返回键兜底** —— 实测返回键会弹出游戏自己的「要退出吗」对话框，越「恢复」越乱

### 识别（不依赖 OCR）

- 圣水：洋红条**最右侧被点亮的列** ÷ 满条宽 × 10（白字会在条上打空洞，空洞不影响最右边界）
- 敌塔血量：粉色血条**宽度就是血量**
- 结算皇冠：金冠 = 已拿、蓝枕 = 没拿，按颜色数色块
- 手牌：10 张卡面模板逐槽匹配（含精英形态两套素材，避免漏牌）
- 自动捡「认不出来的卡面」存盘，供人工补进模板

## 使用说明

### 1. 下载

到 [Releases](https://github.com/yu-echo/MaaCR/releases/latest) 下载 **`MaaCR-win-x86_64-vX.Y.Z.zip`**。

只有 Windows 包 —— 底层识别绑死了 MuMu 模拟器，出别的平台包没意义。

> ⚠️ 发布包目前是**手工组装**的（仓库里已经没有自动化工作流了，见「怎么出包」）。
> Releases 里的包如果比仓库旧，就是没重新组装过。

### 2. 解压，然后双击 `MFAAvalonia.exe`

**解压到纯英文路径**下再跑（中文路径容易出各种怪问题）。里面只有资源（JSON + 模板图），
**没有任何脚本、不需要装 Python、也不用 `pip install` 任何东西**。

如果双击报错、提示缺少 .NET：MFAAvalonia 不是自包含发布，需要 **.NET 10 桌面运行时**。
双击包里的 **`install-deps-win.bat`** 装一下（它走 winget，没有 winget 就自动打开官方下载页），
**装完重启电脑**再试。

### 3. 包里的目录长这样

```
MaaCR-win-x86_64-vX.Y.Z/
├── MFAAvalonia.exe         ← 双击这个
├── install-deps-win.bat    ← 缺 .NET 时才需要
├── interface.json          ← 任务与选项的定义（MFAAvalonia 读它）
├── resource/               ← 模板图与流水线（仓库里的 assets/resource）
├── runtimes/ libs/ plugins/← MaaFramework 的原生库
├── 使用说明.md
└── docs/ README.md LICENSE
```

> 别在这棵树下找 `assets/`：发布包里 `interface.json` 和 `resource/`
> 是**直接跟 `MFAAvalonia.exe` 同层**的，这是 MFAAvalonia 的加载约定。

## 使用前准备

1. **Windows + MuMu 模拟器**（实测 MuMu Player 12），模拟器里装好**国服皇室战争**
   （`com.tencent.tmgp.supercell.clashroyale`）。
2. **分辨率保持 720×1280 竖屏**。本项目全部模板与坐标都是按它量的，
   `interface.json` 里 `display_short_side: 720` 也是为此 —— 换分辨率要重采全部模板并重标坐标。
3. **手动登录一次**。微信 / QQ 授权本工具不碰；识别到登录页会直接停下等你。
4. 模拟器设置里打开 **USB 调试**。
5. **MuMu 窗口别最小化**（更稳的做法是把截图方式换成普通 ADB —— 见下）。
   MaaFramework 会自动探测设备支持哪种截图方式，而 MuMu 只上报「模拟器扩展」
   （`EmulatorExtras`）这一种；这条通道**在窗口最小化 / 息屏时拿不到画面**，
   日志会写 `实时画面为空：截图方式=EmulatorExtras`。放着不管的话，
   任务有可能卡在「正在连接至模拟器……」不动 —— 而界面此时会把新的启动请求忽略掉，
   看起来就是「点了没反应」。**最省心的做法**：MFAAvalonia「设置」里把截图方式
   从「自动」改成 `RawWithGzip`。详见「常见问题」。

> ### 🔒 关于「只驱动模拟器，不碰真机」
> 旧版有一个启动前检查：目标设备不是 `127.0.0.1` 就**拒绝启动**。
> **纯 JSON 化之后这个检查没有了**（它是脚本，已随「去 Python」一起删掉），
> 所以现在**靠你自己选对设备**：MFAAvalonia 里选设备时认准 **MuMu 的 `127.0.0.1:<端口>`**。
> 选错了它就会真的去操作那台设备，没有任何拦截。

## 跑起来

1. 启动 MuMu（不用自己开游戏，工具会把它调到前台）；
2. 开 `MFAAvalonia.exe`，选设备时**选 MuMu 的 `127.0.0.1:<端口>`**；
3. 第一跑就勾「自动战斗」，把「每轮打几局」设成 **1**；
4. 点开始，看日志与 `debug/` 下的识别可视化图。

想一把跑完日常，直接用「**日常一条龙**」预设：
启动游戏 → 领商店礼包 →（自动战斗 + 部落捐赠）× 几轮 → 退出游戏。

> **「跑几轮」在哪设**：在「日常循环」这个任务的设置里，有一个**重复次数**输入框
> （MFAAvalonia 的扩展功能，默认 1）。每重复一次 = 重跑一轮，所以「每轮打几局」
> 填 3 就是**每轮** 3 局 —— 不会像在流水线里那样一轮把总局数打完。
> ⚠️ 这个控件是 MFAAvalonia 独有的，命令行版 `MaaPiCli` 等客户端不认；
> 在那些客户端里「日常循环」只跑一轮。

### 只想验证它认不认得准

第一次跑就把「每轮打几局」设成 **1**，**并且盯着它跑**。

> ⚠️ 这个项目现在**没有任何脚本**，所以也没有「演练模式（只识别不点击）」这种东西 ——
> **它会真的点击你的游戏**。认错了随时点「停止任务」。
> 想先只核对识别、不落点击，用 MFAAvalonia 的「截图 / 识别可视化」：
> 它会画出每个节点识别到哪一块、分数多少，不点也能看。

### 没有自检脚本了

以前有个 `tools/validate.py`（纯标准库的静态自检），能在改 pipeline 之后
抓出「模板路径写错 / `next` 指向不存在的节点 / `entry` 拼错 / 选项覆盖了不存在的节点」
这一类**不报错、只静默失效**的问题。

**它已经随「去 Python」一起删掉了，仓库里现在 0 个 `.py`。** 所以这几类错误现在没有自动拦截，
改完要自己核对，或者用下面的图形化编辑器 —— 它能本地加载资源和流水线、把识别框画出来，
等于把「静默失效」变成「看得见的红框」。

## 从源码跑（开发）

拉下来就能用，**不需要装任何运行时**：

```bash
git clone https://github.com/yu-echo/MaaCR
cd MaaCR
```

然后把 MFAAvalonia 的**数据目录指向本仓库的 `assets/`**（`interface.json` 在里面），
选 MuMu 设备、勾任务、点开始。

改流程就是改 JSON：

| 想改什么 | 改哪里 |
| --- | --- |
| 任务里有哪些步骤、按什么顺序走 | `assets/resource/pipeline/*.json` 的 `next` 列表（**顺序即优先级**） |
| 界面上给用户哪些任务与开关 | `assets/interface.json` 的 `task` / `option` / `preset` |
| 全局延迟、匹配阈值 | `assets/resource/default_pipeline.json` |
| 认图认不准 | `assets/resource/image/` 里的模板图（720×1280 原生截图裁，**不要缩放**） |

### 两种调试方式

**① 图形化调试（看的见）** —— [MaaPipelineEditor](https://github.com/kqcoxn/MaaPipelineEditor)：
本地加载 `assets/`，能可视化节点连接、单节点试跑识别、画出命中框。**推荐用它改流程。**

**② 命令行跑（我自己验证用）** —— `MaaPiCli.exe`：
把 `MaaPiCli.exe` 和它的那堆 `MaaXxx.dll`、`MaaAgentBinary/`、加上本仓库的
`interface.json` + `resource/` 放进同一个目录，然后：

```bash
MaaPiCli.exe -d          # 直接跑（按 config/maa_pi_config.json 里的配置）
MaaPiCli.exe             # 交互模式：会让你选设备、选任务、填参数
```

> ⚠️ `MaaPiCli.exe` 不在单独的 Release 资产里，它在官方主包
> `MAA-win-x86_64-<版本>.zip` 的 `bin/` 目录下。**版本要和包里的
> `runtimes/win-x64/native/MaaFramework.dll` 对上**，混版本起不来。
> 配置别手写 —— 先用交互模式跑一次让它自己写。

### 怎么出包

**目前是手工组装**（原来那条 GitHub Actions 打包流水线已经删掉了，因为它整个是 Python 写的）：

```
MFAAvalonia 的 win-x64 发布包（平铺在包根）
  + 本仓库的 assets/resource/  →  包根/resource/
  + 本仓库的 assets/interface.json（去掉注释、改 version）
  + 使用说明.md
  → zip
```

三个容易忘的点：

1. `interface.json` 必须和 `MFAAvalonia.exe` **同层**，`resource/` 也是；
2. `interface.json` 里 `icon` 引用的图标要一起放进去，否则界面静默用回 MFAAvalonia 自带的图标；
3. **MFAAvalonia 首次启动会改包**：它会删掉包根的 `MaaAgentBinary/`、新建一个空的 `agent/`，
   并写出 `appsettings.json` / `backup/` / `temp/` / `config/` / `logs/` / `debug/`。
   所以**组装完的目录不要先双击开一次再打包**，否则打进去的是「已经被改过」的包。

## 调策略

策略全在 JSON 里，**没有配置文件**：

| 想改什么 | 改哪里 |
| --- | --- |
| 出牌优先级 | `battle.json` 里 `对战循环入口.next` 的顺序（**从上往下试第一张「在手」的牌**） |
| 什么时候出牌 | `出牌-圣水够` 那个 `ColorMatch` 的 `roi` 起点 x —— 圣水条上「够 N 费」的刻度位置。界面上的「对战策略」下拉就是改这个 x |
| 两次出牌间隔 | `出-*` 各节点的 `post_delay` |
| 落点 | `落点` 节点 → `落点-桥头`（`DirectHit`，直接点）/ `落点-破塔深位`（先认左塔血条再点） |
| 换卡组 | 把卡面裁进 `assets/resource/image/cards/`，再在 `battle.json` 加对应的 `出-xxx` 节点并挂进 `对战循环入口.next` |
| 部落最多捐几次 | 界面上的「每次捐赠几张」→ `部落捐一个.max_hit` |
| 商店一屏看多久 | `商店扫屏.timeout`（默认 1.5 秒）—— 商店内容是**懒加载**的，别调太小 |
| 商店最多翻几屏 | **界面上的「商店最多翻几屏」** → `商店滑一屏.max_hit`（默认 60，现在只是**兜底预算**）。正常翻到「每日精选」就收工，实测只滑 17～23 屏 |

> 换卡组时的坑：同一张牌有**普通形态**和**精英/觉醒形态**两套素材，对战时会交替出现。
> 只录一套，轮到另一套那一轮就会认不出来、白白错过出牌机会。
> 每套卡组最多 2 个觉醒位，所以是 8 张牌 + 2 个精英形态 = **10 张模板**，数量固定。

> 日常任务那两条的判据为什么长这样（每一步都对应一次翻车），
> 单独写在了 [`docs/zh_cn/2.2-日常任务.md`](docs/zh_cn/2.2-日常任务.md) —— 想动它们之前先读那一页。

## 目录结构

> 这棵树是**源码仓库**的。发布包的布局不一样（`interface.json` 与 `resource/`
> 跟 `MFAAvalonia.exe` 同层），见上面「包里的目录长这样」。

```
MaaCR/
├── assets/
│   ├── icon.png                    # 界面图标（interface.json 的 icon 指向它）
│   ├── interface.json              # ProjectInterface V2：通用 UI 的入口
│   └── resource/
│       ├── default_pipeline.json   # 全局默认参数（延迟 / 匹配算法与阈值）
│       ├── image/                  # 模板图（720×1280 原生裁剪，勿缩放）
│       │   ├── cards/              #   10 张手牌
│       │   ├── anchors/            #   界面锚点（含开宝箱的多阶段素材）
│       │   ├── nav/                #   底部导航图标（__ 分隔多状态）
│       │   └── shop/ clan/         #   日常任务：「免费」/「已收集」/「免费！」/「捐赠」
│       ├── model/ocr/              #   OCR 模型（det/rec onnx + keys，框架自带，未使用）
│       └── pipeline/               # 任务流水线（**全部逻辑都在这 5 个文件里**）
│           ├── main.json           #   启动链 + 状态分发 + 日常循环 / 退出游戏的入口
│           ├── battle.json         #   各对战界面状态节点
│           ├── daily.json          #   商店免费项 / 部落捐赠
│           ├── base.json           #   通用节点（如「关掉卡牌已收到弹窗」）
│           └── recover.json        #   未知界面自愈
├── docs/zh_cn/                     # 文档：平铺 + 编号（索引见 docs/zh_cn/README.md）
├── deps/tools/                     # 官方 JSON Schema（编辑器补全 / 校验用）
├── tools/install-deps-win.bat      # 装 .NET 10 桌面运行时（发布包里才用得上）
├── logo.png                        # 当前用的图标（README 头部就是它）
├── logo/                           # 8 次 logo 迭代的留档（见 logo/README.md）
└── README.md  LICENSE
```

> **注意：这里没有 `agent/`、没有 `python/`、没有任何 `.py`。**
> 这个项目是**纯 JSON 流水线** —— 全部逻辑都在 `assets/` 里，
> 框架（MaaFramework）自己解释那些 JSON，不需要任何脚本运行时。
> 配套的 `tools/validate.py`、`install.py`、`preflight.py` 和两条 GitHub Actions
> 工作流都在「去 Python」时一并删掉了；**代价是这几件事现在没有自动化**（见下面「没有自检脚本了」）。

## 设计要点

**全部逻辑用 pipeline JSON 表达**（界面锚点、颜色校验、双重确认、多阶段模板、
导航定位、重启游戏），好处是能被通用 UI 与调试器可视化、能离线复算分数、能逐节点看日志。

**状态判定必须「模板 + 颜色」双重确认**，且判定顺序按「误判代价」排：
结算排第一，因为误判会让程序点错按钮（左边紧邻「再来一场」，点错直接再开一局）。
（pipeline 里就是 `And` + 有序的 `next` 列表。）

**「认不出来」≠「卡住」**：加载动画、开宝箱动画都是「认不出来但画面一直在变」，属于正常。
只有「认不出来 **且画面也定格了**」才是真卡住 —— 否则冷启动会被无限重启。

**⚠️ 颜色判据要防「整屏同色」**：`ColorMatch` 判的是「这块 roi 里有多少个目标色像素」。
如果某一屏**整屏都是那个颜色**（比如开宝箱的整屏橙色），roi 里的计数会**直接饱和到 roi 面积**，
看上去就是「命中得比平时还满」—— 这是**假命中**。`主界面锚点` 就踩过一次：
它判底部橙色「对战」按钮，结果在开宝箱橙屏上 count 从正常的 13203 涨到满格 16000，
框架以为到主界面了，后面全在错的屏上瞎撞。
**同一批锚点同时失效、且分数「整体偏低或整体饱和」** 就是这类问题的指纹。

**别用 `cached_image` 当「当前画面」**：它是「上一次识别时」留下的那一帧，
在同一个节点里连着取两次会拿到同一张图。

更多设计取舍与框架语义陷阱见 [`docs/zh_cn/3.2-迁移对照.md`](docs/zh_cn/3.2-迁移对照.md)。

## 常见问题

| 现象 | 先看这里 |
| --- | --- |
| 点「开始任务」没反应，日志停在「正在连接至模拟器……」 | **先看上一次的任务链是不是还卡着。** 界面在「已有任务链正在启动或运行」时会把新的启动请求**直接忽略**（日志原话：`任务启动请求已忽略：当前已有任务链正在启动或运行。`），表现就是「点了没反应」。→ **先点「停止任务」，再重新点开始。** 卡顿本身多半来自截图方式：`EmulatorExtras` 在**模拟器窗口最小化 / 屏幕关闭 / 设备没完全启动**时拿不到画面（日志会写 `实时画面为空：截图方式=EmulatorExtras`）。要么让 MuMu 窗口**保持可见**，要么把截图方式改成 `RawWithGzip`（不依赖窗口可见性） |
| 实时画面一直「暂无截图」/ 一黑一黑 | 同上：`EmulatorExtras` 在窗口最小化 / 息屏时返回**空帧**。让 MuMu 窗口保持可见，或把截图方式改成 `RawWithGzip` |
| 别同时开多个实例 | 每个实例会各自建一套控制器 + adb 连接，容易互相抢。实测见过「已有任务链正在启动或运行」把新请求挡掉，其中一个实例还空着。**同时只跑一个** |
| 任务列表里**一个任务都没有**，只剩「全局设置」 | 界面把上一次的任务布局**缓存**下来了。**点任务栏上面的「+」新建一个实例**，它会重新读一遍，任务就出来了（实测有效）。改过 `interface.json` 之后遇到这种情况，先试这个 |
| **双击 `MFAAvalonia.exe` 报错、起不来** | 缺 .NET 10 桌面运行时。双击 `install-deps-win.bat`，装完**重启电脑** |
| **所有识别都失分（匹配度 0.00）** | 大概率是**屏幕熄了** —— 模拟器闲置会自动熄屏，黑屏时模板匹配全军覆没。先手动点亮模拟器（`环境准备` 节点本来就会发一次亮屏指令，但它只在任务开头跑一次） |
| 卡在某一屏来回打转 | 看日志里反复出现的是哪两个节点名。`清障链 ⇄ 再等等` 空转 = **启动链没认出任何已知界面**（多半是弹窗遮罩或动画没结束）；`商店扫屏 ⇄ 商店滑一屏` 一直重复 = 商店确实在往下翻，等它翻完（默认最多 60 屏，可在界面上调小） |
| 报「界面未知」然后重启游戏 | 自愈走到了最后一段（`未知-重启`）。说明那一屏既不认识、画面也不动了。把那一屏截图发出来补个锚点就好 |
| 一直不出牌 | 检查 `出牌-圣水够` 的 roi 起点位置（对应界面上「对战策略」那个下拉），以及手牌模板有没有对上。认不出就是卡面模板缺了精英/觉醒形态 |
| 出牌点下去没反应 | 坐标落在两行按钮中间的空隙上，点了等于没点还不报错。每个写死坐标都要在截图上肉眼确认过 |
| 部落一个都没捐出去 | 看「部落捐一个」的 OCR 结果。它认的是 `捐赠` 这两个字（`threshold 0.3`），认到 0 个说明这屏确实没有可捐的请求；也可能是按钮是灰的（自己发起的请求，本来就捐不了） |
| 选错设备（驱动到真机了） | **纯 JSON 化之后没有设备安全检查了**（那个检查是 `tools/preflight.py`，已删）。所以只能靠你自己在 MFAAvalonia 里选对 **MuMu 的 `127.0.0.1:<端口>`**，没有兜底 |
