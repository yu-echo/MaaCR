# 3.1 从源码跑与调试

> 这一页给**要改流程 / 改素材**的人。只想把它跑起来，看 [1.1-快速开始](1.1-快速开始.md)。

## 一、拉下来就能跑

```bash
git clone https://github.com/yu-echo/MaaCR
cd MaaCR
```

**不需要装任何运行时**（本项目只有 JSON）。把 MFAAvalonia 的**数据目录指向本仓库的
`assets/`**（`interface.json` 在里面），选 MuMu 设备、勾任务、点开始。

改流程就是改 JSON：

| 想改什么 | 改哪里 |
| --- | --- |
| 任务里有哪些步骤、按什么顺序走 | `assets/resource/pipeline/*.json` 的 `next` 列表（**顺序即优先级**） |
| 界面上给用户哪些任务与开关 | `assets/interface.json` 的 `task` / `option` / `preset` |
| 全局延迟、匹配阈值 | `assets/resource/default_pipeline.json` |
| 认图认不准 | `assets/resource/image/` 里的模板图（720×1280 原生截图裁，**不要缩放**） |

> **具体「调策略」的对照表**（出牌优先级 / 落点 / 换卡组 / 商店翻几屏……）在
> [2.3-调策略](2.3-调策略.md)。

## 二、目录结构

> 这棵树是**源码仓库**的。发布包的布局不一样（`interface.json` 与 `resource/`
> 跟 `MFAAvalonia.exe` 同层），见 [1.1-快速开始](1.1-快速开始.md)。

```
MaaCR/
├── assets/
│   ├── icon.png                    # 界面图标（interface.json 的 icon 指向它）
│   ├── interface.json              # ProjectInterface V2：通用 UI 的入口
│   └── resource/
│       ├── default_pipeline.json   # 全局默认参数（延迟 / 匹配算法与阈值）
│       ├── image/                  # 模板图（720×1280 原生裁剪，勿缩放）
│       │   ├── cards/              #   手牌（含精英/觉醒形态，共 10 张）
│       │   ├── anchors/            #   界面锚点（含开宝箱的多阶段素材）
│       │   ├── nav/                #   底部导航图标（__ 分隔多状态）
│       │   ├── shop/ clan/         #   日常任务：「免费」/「已收藏」/「免费！」/「捐赠」
│       │   └── card_library/       #   全卡牌参考图库（**不是模板**，见 2.3）
│       ├── model/ocr/              #   OCR 模型（框架自带）
│       └── pipeline/               # 任务流水线（**全部逻辑都在这 5 个文件里**）
│           ├── main.json           #   启动链 + 状态分发 + 日常循环 / 退出游戏的入口
│           ├── battle.json         #   各对战界面状态节点
│           ├── daily.json          #   商店免费项 / 部落捐赠
│           ├── base.json           #   通用节点（如「关掉卡牌已收到弹窗」）
│           └── recover.json        #   未知界面自愈
├── docs/zh_cn/                     # 文档：平铺 + 编号（索引见 docs/zh_cn/README.md）
├── deps/                           # 官方 JSON Schema（编辑器补全 / 校验用）
├── tools/                          # 工作脚本（**不进发布包**）
├── logo.png  logo/                 # 当前图标 + 历代 logo 留档
└── README.md  LICENSE
```

> **注意：这里没有 `agent/`、没有 `python/`、没有任何 `.py`。**
> 这个项目是**纯 JSON 流水线** —— 全部逻辑都在 `assets/` 里，框架（MaaFramework）
> 自己解释那些 JSON，不需要任何脚本运行时。

## 三、两种调试方式

### ① 图形化（看的见）—— 推荐

[MaaPipelineEditor](https://github.com/kqcoxn/MaaPipelineEditor)：本地加载 `assets/`，
能可视化节点连接、单节点试跑识别、画出命中框。**改流程优先用它。**

MFAAvalonia 本身也能看：它的「截图 / 识别可视化」会画出每个节点识别到哪一块、分数多少，
**不落点击也能看**。

### ② 命令行（无头）

`MaaPiCli.exe -d` 直接把任务跑起来，不开界面。**摆文件、生成配置的步骤见
[1.1-快速开始](1.1-快速开始.md#b-纯流水线命令行maapicli)**。

> ⚠️ `MaaPiCli.exe` 不在单独的 Release 资产里，它在官方主包
> `MAA-win-x86_64-<版本>.zip` 的 `bin/` 下。**版本要和包里的
> `runtimes/win-x64/native/MaaFramework.dll` 对上**，混版本起不来。

## 四、怎么验证改动

### 4.1 ⚠️ 现在没有静态自检脚本了

以前有个 `tools/validate.py`（纯标准库的静态自检），能在改 pipeline 之后抓出
「**模板路径写错** / `next` 指向不存在的节点 / `entry` 拼错 / 选项覆盖了不存在的节点」
这一类**不报错、只静默失效**的问题。

**它已随「去 Python」一起删掉，仓库里现在 0 个 `.py`。** 所以这几类错误没有自动拦截 ——
改完要么自己核对，要么用上面的图形化编辑器，它能把「静默失效」变成「看得见的红框」。

### 4.2 看 `debug/vision/` 的图（排查「认不到」的第一手材料）

开了 `maa_option.json` 的 `save_draw: true` 之后，**每一次识别尝试**都会在
`debug/vision/` 存一张 jpg：`<时间戳>_<节点名>_<reco_id>.jpg`。

里面是 **MaaFramework 自己看到的那一帧 + 它画的识别框 + 分数**，文件名带节点名。
它能直接回答三个问题：

- 它看到的到底是哪个界面？
- 识别框画在哪、分数多少？（能一眼分清「没认出」和「认出了但框错位置」）
- 命中之后界面变成了什么？（看下一个节点的图）

### 4.3 看 `debug/maafw.log`

```bash
# ⚠️ 这个日志是跨多次运行累积的，一定要带日期前缀过滤
grep -a "2026-10-01" debug/maafw.log | grep -a "你的节点名"
```

`TemplateMatcher::analyze` 那行会给出 `all_results_` / `best_result_`（含 box 和 score），
标定与诊断都用它，不必自己重跑 OpenCV。

### 4.4 验收标准（拿结果验收，别拿「跑通了」验收）

- **正样本最低分 ≥ 阈值 且 负样本最高分 < 阈值**，中间要有空档；
- 任务以 `### All tasks have been completed ###` 收尾、**无 ERR**；
- **跑两遍结果一致**（第二次不因状态残留出岔子）。
