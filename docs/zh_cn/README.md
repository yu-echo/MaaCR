## 现在的实测状态

**对战与日常流程都已经在真实 MuMu 上跑通过**：

- 自动战斗：连打 2 局全部打完、4 分 28 秒、零重启，`主界面` 计数正好 2（计数准确）——2026-09-24；
- 日常一条龙：启动 → 领商店礼包 →（自动战斗 + 部落捐赠）× 轮数 → 关游戏，全链路跑通；
- **商店补偿礼包**（「维护 / 异常补偿」）：两款礼包均自动领取成功，
  识别分数 0.997 / 0.996，任务以 `All tasks completed` 收尾、无 ERR ——2026-09-30；
- 命令行（`MaaPiCli`）与图形界面（`MFAAvalonia`）两条路都验过。

还没验或没把握的：

- 每轮之间**没有间隔**，直接进部落 —— 会不会被判定异常没验；
- 少数界面（商店各子标签、社交页、训练日预览页）没做锚点，靠自愈兜底；
- 「防守判断」还没做，胜率不是它的目标（目标是**每局耗时**）。

## 文档本身的约定

- 放在 `docs/zh_cn/` 下，**平铺 + 编号**，不建子目录（跟框架文档一致）；
  章节含义：`1.x` 入门、`2.x` 原理、`3.x` 开发、`4.x` 教程、`5.x` 排错。新增一页就往后排号。
- **README 保持精简**：只放概述、功能列表与导航；凡是「怎么做 / 为什么这么做」的内容
  一律写进这里对应的页，README 里只留一行链接。
- 链接一律用**相对路径** —— 发布包里也带了 `docs/`，这样在解压出来的文件夹里也点得开。
- 说「怎么做」的同时说清「为什么这么做」：这个项目的判据大半是被踩过的坑逼出来的，
  只写结论的话下一个人很容易「顺手简化」回去。
