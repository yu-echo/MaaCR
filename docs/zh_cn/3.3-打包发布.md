# 3.3 打包发布

> 发布包**不是把仓库原样压缩** —— 布局不一样，而且有几个必须记住的坑。
> 这一页也是「发一版新包」的完整清单。

## 一、包的结构

```
MFAAvalonia 的 win-x64 发布包（平铺在包根）
  + 本仓库的 assets/resource/                      →  包根/resource/
  + 本仓库的 assets/interface.json（去注释、改 version）
  + 本仓库的 README.md + docs/                     →  包根同名
  + 使用说明.md（面向小白的快速上手）
  → zip（「包名/内容」单层套娃）
```

## 二、三个容易忘的点

1. **`interface.json` 必须和 `MFAAvalonia.exe` 同层**，`resource/` 也是
   —— 别在这棵树下找 `assets/`，那是**源码仓库**的布局。
2. `interface.json` 里 `icon` 引用的图标**要一起放进去**，否则界面会**静默**用回
   MFAAvalonia 自带的图标。
3. ⚠️ **组装完的目录不要先双击开一次再打包**。MFAAvalonia 首次启动会**改包**：
   删掉包根的 `MaaAgentBinary/`、新建空的 `agent/`，并写出
   `appsettings.json` / `backup/` / `temp/` / `logs/` / `debug/`。
   打进去的就成了「已经被改过」的包 —— 实测条目数会从 578 掉到 435、缺 78 个文件。
   > 所以打包脚本对这几样做了**硬拦**：发现有启动痕迹就拒绝出包，不给「打包完成」的假象。

## 三、为什么包里要预置一份「实例配置」

**不预置的话，全新解压的包第一次打开必定是空任务列表**（必现，不是偶发）。

原因在 MFAAvalonia 的时序缺陷：目录里没有任何实例配置时，它会基于 preset 建初始实例，
但那次 `ApplyPreset` 跑在**任务模板还没加载**之前 —— 按任务名查不到就跳过，
于是 6 个任务全被丢弃、实例被写成 `CurrentTasks: []`。
后面的补救分支又因为 `ViewModel == null` 被跳过。

**办法**：包里直接放一份写好的 `config/instances/<id>.json`
（`CurrentTasks` + `TaskItems` 都填好），启动时「未找到实例配置」这个条件不成立，
就不会走那条坏路径。

## 四、实际操作（本机固化的脚本）

打包脚本在**工作区**（不在仓库里，所以不会进包），把它当成四步走：

```bash
# 1) 组装（从 build/ 里的外壳复制，剔掉 Python 运行时，覆盖 resource / README / docs）
python tools/build_package.py v1.0.0 --no-zip

# 2) 手工往包根放一份 面向用户的「使用说明.md」（脚本不会自动生成它）

# 3) 预置实例配置（绕开上面那个首次启动缺陷）
python tools/preset_instance.py MaaCR-win-x86_64-v1.0.0

# 4) 打 zip
python tools/build_package.py v1.0.0
```

**两个细节**：

- 第 1 步和第 4 步**用的是同一个脚本**：目标目录已存在时它走「原地更新」，
  并保留你放进去的 `使用说明.md`；所以第 2 步必须在第 4 步**之前**做。
- zip 里的中文文件名是 **GBK 编码、且不设 UTF-8 标志位**（跟历代包一致，
  中文 Windows 解压最稳）。用别的工具读 zip 时中文可能显示成乱码，属正常。

## 五、出包后的自检

脚本会自己打印这几项，**任何一项 ✗ 都不要发**：

| 检查 | 期望 |
| --- | --- |
| 包内 `.py` 数量 | **0**（纯 JSON 项目） |
| 首次启动痕迹（`agent/` `backup/` `temp/` `logs/` `debug/`） | 无 |
| 包根 `MaaAgentBinary/` | 存在（缺了 MaaPiCli 用不了） |
| `interface.json` 的 `version` | 等于本次版本号 |
| 任务 / 预设 | 与预期一致 |

> 更省事的做法：把包**解压到别处再真跑一次**（尤其第一次启动的任务列表）。

## 六、发一版新版本（发布清单）

1. 改 `assets/interface.json` 的 `version`？—— **不用**，第 1 步的脚本会按传入的版本号写包内那份；
2. 按上面四步出包；
3. 把包上传到 GitHub Release（资产名用 `MaaCR-win-x86_64-<版本>.zip`）；
4. Release 正文开头写明**下载方式**和**已知限制**（只支持国服 + 720×1280 竖屏）。
