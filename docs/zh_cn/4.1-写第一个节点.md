# 4.1 写你的第一个节点

> **这一页的目标**：让脚本「认出一张图 → 点下去」。
> 全程只改 **一个 JSON 文件**，不写任何代码 —— 这个项目没有 Python、没有脚本，**流程就是 JSON 本身**。
>
> 跟完这一页，你会得到一个能真正跑起来的节点。

## 一、先搞懂一个「节点」长什么样

MaaFramework 里，**一个节点 = 一句话**：

> **看到什么**（识别）→ **做什么**（动作）→ **接着去哪**（next）

最简单的节点长这样：

```json
"点底部商店": {
    "recognition": {
        "type": "TemplateMatch",
        "param": {
            "template": "nav/shop.png",
            "roi": [0, 1140, 720, 140],
            "threshold": 0.6
        }
    },
    "action": { "type": "Click", "param": {} },
    "next": []
}
```

怎么读：

| 字段 | 意思 |
| --- | --- |
| `recognition.type` | **怎么认**。`TemplateMatch` = 「在屏幕里找一张长得像 `nav/shop.png` 的图」 |
| `template` | 模板图的路径，**相对 `assets/resource/image/`** |
| `roi` | 「只在屏幕这一小块里找」，格式 `[x, y, 宽, 高]`。**不写就是全屏找** |
| `threshold` | 相似度门槛。`0.6` = 至少 60% 像才算认到 |
| `action` | 认到之后**做什么**。`Click` + `param: {}` = 「点它认到的那个位置」 |
| `next` | 做完之后**去哪**。写节点名，`[]` 表示结束 |

> 💡 **`roi` 是新手最容易漏、也最有用的一个字段**。
> 不写 `roi` = 全屏找，屏幕上任何一个长得像的角落都可能被误认成目标。
> 上面例子里 `[0, 1140, 720, 140]` 的意思是「只在屏幕最底下那 140 像素里找」——
> 因为底部导航栏就在那儿，别处不可能有商店图标。

## 二、准备一张模板图（这一步决定成败）

模板图 = 「你要认的那个东西」的截图。**这一步做错，后面全白搭。**

### 1. 截图

用模拟器自带的截图，或：

```bash
adb -s <你的设备> exec-out screencap -p > shot.png
```

⚠️ **必须是 720×1280 的原始截图**。本项目所有模板和坐标都是按这个分辨率量的，
`interface.json` 里 `display_short_side: 720` 也是为此。
（用别的分辨率不报错，但会**认不到**，而且不告诉你原因。）

### 2. 裁出目标

用任何画图工具，把目标**框出来另存为 PNG**。裁剪时守两条铁律：

- ✅ **只裁「不会变」的部分**。一个按钮，就只裁按钮本身。
- ❌ **别把会变的东西裁进去**：选中/未选中态的颜色、未读红点、旁边的文字、底部的浅色描边……

> **真实翻车例子**：本项目底部的社交图标，原来连「图标底色」一起裁了。
> 后来游戏把未选中态的底色从灰蓝换成金黄，模板直接失配（相似度掉到 0.48），
> 部落任务 20 秒超时失败。
> 修法是**只裁图标本体**，让底色变成背景 —— 两种底色都能过阈值。

### 3. 存到正确的位置

放进 `assets/resource/image/` 下的子目录，比如：

```
assets/resource/image/
├── nav/          ← 底部导航（本项目惯例：__ 分隔多状态，如 shop.png / shop__.png）
├── shop/ clan/   ← 按功能分
└── cards/        ← 手牌
```

> **`image/card_library/` 不是模板库**。那一百多张是「收藏页的卡面缩略图」，
> 尺寸和实际识别场景对不上（收藏页 158×194、请求弹窗 147×126、手牌 101×126），
> 拿它当模板匹配只有 0.61 分。**它只是给你查「这是哪张卡」用的参考图。**

## 三、把节点写进流水线

打开 `assets/resource/pipeline/` 下的某个 JSON（按用途选：`main.json` 主界面、
`battle.json` 对战、`daily.json` 日常、`recover.json` 自愈），加一个节点：

```json
    "点底部商店": {
        "recognition": {
            "type": "TemplateMatch",
            "param": {
                "template": "nav/shop.png",
                "roi": [0, 1140, 720, 140],
                "threshold": 0.6
            }
        },
        "action": { "type": "Click", "param": {} },
        "post_delay": 2500,
        "next": ["下一步"],
        "on_error": ["下一步"]
    },
```

新增的两个字段：

| 字段 | 意思 |
| --- | --- |
| `post_delay` | 动作做完**等多久**（毫秒）再做下一步。点击后界面要加载，必须留时间 |
| `on_error` | **没认到**（或动作失败）时去哪。**强烈建议别留空**，见下 |

### `on_error` 为什么必须写

不写 `on_error`，节点认不到就是**整条任务直接结束**，而且日志看着像「正常跑完了」。

本项目有一条通用原则（用户定的）：

> **任何一步失败，都要先重新识别当前界面。**

所以本项目的写法是「失败就回扫屏节点，别停」：

```json
"on_error": ["商店扫屏"]
```

### 让别的节点走进来

写好了不代表会被执行 —— 得有人 `next` 到你。找到入口节点，把它加进列表：

```json
"商店扫屏": {
    "next": ["商店领维护礼", "点底部商店", "商店到每日精选"]
}
```

⚠️ **`next` 列表的顺序 = 优先级**。框架**从上往下依次尝试**，**第一个认到的**执行。
所以「越具体、越该优先做的事」要排在越前面。

## 四、标定阈值：别靠感觉，量出「分离度」

这是新手最容易跳过、又最该做的一步。

**要证明两件事**：

1. **该认的能认到** —— 正样本的最低分 ≥ 阈值；
2. **不该认的不会认到** —— 负样本的最高分 < 阈值。

两个分数之间要有**空档**，阈值放在空档中间就是安全的。

### 怎么量（OpenCV，和框架同一个算法）

框架的 `TemplateMatch` 默认 `method=5`，就是 `cv2.TM_CCOEFF_NORMED`，
**阈值可以直接照搬，不用换算**：

```python
import cv2, numpy as np

# ⚠️ 路径含中文时 cv2.imread 会返回 None，必须这么读
tpl = cv2.imdecode(np.fromfile('tpl.png', dtype=np.uint8), cv2.IMREAD_COLOR)
img = cv2.imdecode(np.fromfile('frame.png', dtype=np.uint8), cv2.IMREAD_COLOR)

r = cv2.matchTemplate(img, tpl, cv2.TM_CCOEFF_NORMED)
_, mx, _, loc = cv2.minMaxLoc(r)
print('最高分', round(mx, 4), '位置', loc)
```

- **正样本**：目标出现的那些帧 → 记 **最低分**
- **负样本**：整页其余屏 + **最容易混的那个东西** → 记 **最高分**

> **真实例子**（2026-09-30 标定商店补偿礼包的「免费！」按钮）：
> 正样本 **0.9964 ~ 0.9970**；负样本最高 **0.6382**（「每日精选」那张**浅绿底**的「免费！」卡）；
> 整页其余位置全部 **≤ 0.4033**。→ 阈值取 **0.85**，正好落在空档正中。

⚠️ **只测正样本 = 没测**。负样本里最该测的是「**长得像但含义不同**」的那个东西 ——
上例里就是另一张同样写着「免费！」、只是底色不同的卡。**同一个词出现在两个地方**，
是这个项目最常见的误判来源。

## 五、跑起来验证

**别用「文件写完了」当验证。**

改完 JSON，用 [MaaPipelineEditor](https://github.com/kqcoxn/MaaPipelineEditor) 可视化看，
或者用 `MaaPiCli.exe -d` 无头实跑（见 [README 的「从源码跑」](../../README.md#从源码跑开发)）。

跑完看两个地方：

| 看哪 | 得到什么 |
| --- | --- |
| `debug/maafw.log` | 每次识别的 `all_results_` / `best_result_`（含 box 和 score） |
| `debug/vision/*.jpg` | **框架自己看到的那一帧 + 它画的识别框 + 分数**，文件名带节点名 |

`debug/vision/` 那批图是排查「认不到」的**第一手材料** ——
它能直接告诉你框架看到的是哪个界面、框画在哪、分多少，
比在屏幕前猜「它到底看到了什么」快一个数量级。

⚠️ `debug/maafw.log` 是**跨多次运行累积**的，搜的时候记得带日期前缀：

```bash
grep -a "2026-09-30" debug/maafw.log | grep -a "我的节点名"
```

## 六、一句话总结

> **一张 720p 原图裁的模板 + 一个够窄的 `roi` + 一个量出来的阈值 + 一条不断链的 `on_error`**
> —— 这四样齐了，节点才站得住。
