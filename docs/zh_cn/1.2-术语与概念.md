# 1.2 术语与概念

看日志、改 pipeline、翻框架文档时会撞到的词。左边是通用叫法，右边是**它在这个项目里具体指什么**。

## 框架侧（MaaFramework / MFAAvalonia）

| 词 | 是什么 |
| --- | --- |
| **MaaFramework** | 底层自动化框架：负责截图、识别、执行动作。本项目跑在它上面 |
| **MFAAvalonia** | 通用图形界面（一个 .NET 程序）。它读 `interface.json` 决定显示哪些任务与选项 |
| **Controller / 控制器** | 「怎么操作设备」。本项目用 `Adb` 控制器，连 MuMu 的 `127.0.0.1:<端口>` |
| **Resource / 资源包** | `assets/resource/`：模板图 + pipeline JSON |
| **Tasker / Context** | 跑任务的执行体与上下文。自定义动作里拿到的 `context` 就是它，用它点坐标、截图 |
| **Pipeline / 流水线** | 一串 JSON 节点。每个节点 = 一次「识别」；认到了就执行动作、再走向 `next` |
| **节点（node）** | pipeline 里的一个 JSON 对象，有名字，比如 `对战中`、`结算界面` |
| **`next`** | 当前节点识别成功**之后**要走的候选节点列表，**有序**（按误判代价排） |
| **`on_error`** | 当前节点的 `next` 超时、或动作失败时去哪 |
| **Custom 识别 / 动作** | 框架自带算法表达不了的逻辑，用 Python 写好后注册进去 |
| **Agent** | 跑 Custom 代码的那个 Python 进程，入口 `agent/main.py` |
| **`interface.json`** | ProjectInterface V2 协议文件：告诉通用界面有哪些任务、哪些选项、agent 怎么起 |
| **pretask / 预任务** | 控制器建立**之前**执行的程序。本项目用它做「环境准备」 |
| **`green_mask`** | 匹配时把模板里不关心的部分涂绿从而跳过。**只作用于模板侧** |
| **`cached_image`** | 框架缓存的那一帧，是**上一次识别时**留下的，不等于当前画面 |

## 本项目侧

| 词 | 是什么 |
| --- | --- |
| **环境准备** | `tools/preflight.py`。① 确认目标设备是本地模拟器（不是插着的真机）；② 模拟器没跑就自己拉起来 |
| **三级自愈** | 认不出界面时的兜底阶梯：① 点底部导航回主界面 → ② 当全屏弹层点 → ③ 判定真卡住就重启游戏 |
| **白字掩码匹配** | 判「免费」这类**白字**的匹配法：画面与模板**都**先二值化成「是不是白像素」再比 |
| **`dry`** | Agent 里的状态位 `state.dry`：置真则只识别不点击。**界面上已没有入口**（演练模式已去掉），只在无头调试时由 pipeline override 注入 |
| **`MaaDriver`** | Agent 里对 `context` 的一层薄封装（`shot()` / `tap()`），方便写测试与复用 |

## 四个最容易搞反的语义

这四条都是移植时逐字读框架源码/文档确认过的，改动相关逻辑前先读一遍：

1. **`timeout` 不是「这个节点的超时」**，而是「当前节点的 **`next` 列表**的循环识别超时」。
   两个推论：
   - 往 `next` 里多塞一个候选节点**不额外花时间**（每轮按顺序全试一遍，命中就停）；
   - `next` 里**必须有一个必定命中的兜底节点**，否则整条链会超时结束（看起来像「任务莫名跑完」）。
2. **`green_mask` 只盖模板侧**，画面侧不管；而且官方明确写了「常规背景变化通常无需使用」、
   「避免过度涂抹导致主体边缘特征丢失」。所以本项目的白字匹配**没有**用它，
   而是在 Agent 里对画面与模板都做二值化。
3. **`wait_freezes` 是「等它不动」**。本项目判「商店滑到底」要的是「画面**还在不在动**」——
   语义正好相反，所以那段也留在 Agent 里。
4. **`cached_image` 不能当当前画面**。在自定义动作里连着取两次会拿到同一张图；
   要真帧得走 `post_screencap()`。

[`maafw.xyz/docs/3.1-PipelineProtocol`](https://maafw.xyz/docs/3.1-PipelineProtocol)
（「执行逻辑」与「节点生命周期」两节），字段清单可以直接读
