# 1.1 快速开始

给「只想把它跑起来」的人。想改流水线的话，直接从 [2.1-识别原理](2.1-识别原理.md) 开始。

本项目**只有 JSON**：没有 Python、没有自定义识别/动作、没有 agent 子进程。
一个任务的完整逻辑就是 `assets/resource/pipeline/*.json` 里的节点与 `next` 关系。
所以「怎么跑」也有两条路，选一条就行：

| 跑法 | 要什么 | 适合 |
| --- | --- | --- |
| **A. 图形界面**（发布包） | 下载解压，双击 `MFAAvalonia.exe` | 平时用 |
| **B. 纯流水线命令行**（MaaPiCli） | 自己下一个官方 `MaaPiCli`，摆进项目根 | 「不要 Python、不要界面」的最干净跑法 |

> 两条路跑的是**同一份 JSON**，行为完全一样。B 那条只是没有界面。

## 先确认三件事

1. **Windows** —— 本项目只发 Windows 包（底层绑死了 MuMu 模拟器）。
2. **MuMu 模拟器**（实测 MuMu Player 12）里装好**国服皇室战争**
   （`com.tencent.tmgp.supercell.clashroyale`），并且你**已经手动登录过一次** ——
   微信 / QQ 授权本工具不碰，识别到登录页它会停下等你。
3. 模拟器保持 **720×1280 竖屏**，设置里打开 **USB 调试**。

> 分辨率别改。本项目全部模板图与坐标都是按 720×1280 量的，
> `interface.json` 里的 `display_short_side: 720` 也是为此 —— 换分辨率要重采全部模板并重标坐标。

## A. 图形界面

1. 到 [Releases](https://github.com/yu-echo/MaaCR/releases/latest) 下载
   **`MaaCR-win-x86_64-vX.Y.Z.zip`**；
2. **解压到纯英文路径**下（中文路径容易出各种怪问题）；
3. 双击 **`MFAAvalonia.exe`**。

如果双击报错、提示缺少 .NET：双击包里的 **`install-deps-win.bat`** 装一下
（缺 .NET 10 桌面运行时才会用到它），**装完重启电脑**再试。

## B. 纯流水线命令行（MaaPiCli）

MaaPiCli 是 MaaFramework 官方的命令行客户端：它只读 `interface.json` + `resource/`，
把任务跑起来，**不需要任何脚本**。

### B1. 摆文件

MaaPiCli **不在** MAA 主包里，要单独下：

1. 从 [MaaFramework Releases](https://github.com/MaaXYZ/MaaFramework/releases)
   下载 **`MAA-MaaPiCli-windows-x86_64-v5.12.3.zip`**；
   > 版本号要对上 `maafw-version.txt` 里锁的 MaaFramework 版本（当前 `v5.12.3`）。
   > MaaPiCli 和 runtime 版本不匹配会直接起不来。
2. 把压缩包 `bin/` 里的**所有文件**（`MaaPiCli.exe` + 一堆 `.dll`）
   解压到**本项目根目录** —— 也就是和 `interface.json`、`resource/` 同级。

摆完大概是这样（`MaaPiCli.exe` 必须和 `interface.json` 在一起）：

```
MaaCR/
├── MaaPiCli.exe          ← 解压进来的
├── MaaUtils.dll          ← 解压进来的一堆 dll
├── MaaFramework.dll
├── ...
├── interface.json        ← 本项目
├── resource/             ← 本项目（pipeline + image + model/ocr）
└── config/
    └── maa_pi_config.json
```

> ⚠️ MaaPiCli 的工作目录必须是**含 `interface.json` 的那一层**。
> 单独把 `MaaPiCli.exe` 拷出来、不带那几个 dll，会报
> `MaaUtils.dll: cannot open shared object file` 然后静默退出。

### B2. 第一次：用交互模式让它自己生成配置

**不要手写配置** —— 里面的设备名必须和 MaaToolkit 扫出来的名字**一模一样**，
写错不会报错，只会静默回退成空参数、最后在创建控制器时失败。让程序自己写最稳。

在项目根目录开一个终端：

```bat
MaaPiCli.exe
```

依次回答：

| 提示 | 选什么 |
| --- | --- |
| `### Select ADB ###` | `1`（Auto detect，自动探测） |
| `## Select Device ##` | 你 MuMu 那一项 —— 形如 `1. MuMu安卓设备-MuMuPlayer v5+` / `127.0.0.1:16384` |
| `局数 [1]:` | 直接回车（先用 1 局试） |

选完它会自己往 `config/maa_pi_config.json` 写配置，然后开跑。
以后就可以直接 `-d` 跳过问答。

### B3. 以后再跑

```bat
MaaPiCli.exe -d
```

`-d` = 用已经存好的 `config/maa_pi_config.json` 直接跑，不再问任何问题。

### B4. 想看自己在干什么

命令行**只会打印菜单和最后的结论**。真正的过程在框架日志里：

```bat
type debug\maafw.log
```

日志里能看到它当前走到哪个节点、识别到了什么（`Node.PipelineNode.Starting` / `Node.Recognition.Succeeded`）。
认不准的时候 `debug/on_error/` 会留下一张当时的截图。

## 第一次跑：只跑 1 局，盯着看

1. 启动 MuMu（**不用自己开游戏**，工具会把它调到前台）；
2. 设备选 **MuMu 的 `127.0.0.1:<端口>`**（别选插着的真机，理由见下）；
3. 勾「自动对战」，把「最多打几局」设成 **1**（走 B 那条就把配置里的 `局数` 填 `1`）；
4. 点开始 / 执行，**别离开电脑，盯着它跑**。

> ⚠️ **它会真的点击你的游戏。** 本版本已经去掉了「演练模式（只识别不点击）」开关，
> 所以第一次跑务必把局数设成 1、认错了随时手动停。

## 为什么非要选模拟器，不选真机

旧版实测过一个坑：开发机**插着的真机上装了同一个国服包**，所以按包名挑设备根本区分不开；
一旦模拟器端口全断、程序回退到「第一台在线设备」，就会去操作真机。

现在**没有 Python 做前置检查了**（旧的 `tools/preflight.py` 已随之删除），
所以这根安全线改由**你选设备**来守：两个客户端都只会去连你在界面上 / 配置里指定的那一个
`adb_path` + `address`。**别把 address 填成真机。**

## 日常任务

界面里「日常任务」分组有两项（领商店免费项、部落捐赠），
也可以直接用「**日常一条龙**」预设一把跑完（商店 + 部落，跑完自动回主界面）。

它们各自在判什么、为什么这么判，见 [2.2-日常任务](2.2-日常任务.md)。

## 跑起来之后出问题

看 [README 的「常见问题」](../../README.md#常见问题) 那张表 —— 按「现象」列了你该先看哪里，
