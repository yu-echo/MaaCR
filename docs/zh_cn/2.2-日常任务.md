# 日常任务：商店免费项 / 部落捐赠

> 全部判据都在 `assets/resource/pipeline/daily.json` 里，**没有一行 Python**。
> 这一页记的是**为什么这么写** —— 每条都对应一次实机踩坑，改之前先读完。

---

## 一、整体形态

```
商店任务 ──> 环境准备 ──> …整条启动链… ──> 主界面锚点 ──> 商店去商店页
                                                     └─> 商店进礼物盒 ──> 商店选超值推荐
                                                     └─> 商店扫屏 ⇄ 商店滑一屏 … ──> 商店扫到底
                                                                                        └─> 收尾回主界面

部落任务 ──> 环境准备 ──> …整条启动链… ──> 主界面锚点 ──> 部落进入聊天 ──> 部落点聊天入口
                                                     └─> 部落扫屏 ⇄ 部落翻页 … ──> 部落扫到底
                                                                                     └─> 部落退出聊天
```

⚠️ **启动链末端必须由 `interface.json` 的任务级 `pipeline_override` 挂钩子。**
`环境准备` 是 `DirectHit`、永远命中，所以任何任务都会先走完整条启动链，最后停在
`主界面锚点` 上。而 `主界面锚点` 的 `next` 默认是**空的** —— 协议里 `next` 为空 = 任务终止。
不接这根线，任务会在到达主界面之后就结束，下面所有节点一次都跑不到。

## 二、商店：领免费项

### 真实路径（2026-09-24 实机逐步走通）

```
底部「商店」→ 左上「礼物盒」分类 → 「超值推荐」页签 → 慢速下翻 20 屏以上
           → 「每日精选」区 → 点第一格的浅绿「免费！」卡
           → 弹窗「获取宝石？」→ 点绿色「免费！」按钮 → 卡片变「已收集！」
```

节点对应关系：`商店去商店页` → `商店进礼物盒` → `商店选超值推荐` → `商店扫屏`/`商店滑一屏` → `商店领免费项` → `商店确认免费`。

**`商店进礼物盒` 不是「去领礼物」**，它是**把页面复位到「超值推荐」顶部**：
商店页会记住上次的滚动位置，复位之后「翻 20+ 屏找每日精选」才是从确定的位置出发。
（已经是礼物分类时再点一次是幂等的，不会出事。）

### 实测数据（MuMu 720×1280）

| 项 | 值 | 怎么来的 |
| --- | --- | --- |
| 底部导航角标 y | 1155 ~ 1185 | 红角标连通域，三个角标一致 |
| 礼物盒图标 | 中心 (130, 165)，盒身 70×58 | 顶部图标行 4 格等距，只裁盒身 |
| 「免费！」文字 | 卡面左列，(110, 421±) | 模板在全屏搜到 NCC = **1.000** |
| 弹窗绿色「免费！」 | 中心 (360, 807)，169×77 | 同上，NCC = **1.000** |
| 免费卡底色 | `(97,237,152)` / 实测 `(93,221,140)` | 模板就是从这张卡上裁的 |
| 弹窗按钮底色 | `(58,228,73)` | 与卡面绿**不同色**，所以两套模板不会互窜 |

### 「免费！」用模板，不用 OCR

两个字是「白字 + 深色描边」，压在浅绿卡面上，而 `白字掩码` 的 `S ≤ 40`
与卡面绿的 `S ≈ 43~58%` **只差一点点** —— 靠得太近，卡面一被算成白，
字就淹没在白块里。而原色模板跟卡面是同一张图裁的，颜色/字号完全对得上，
实测同屏 NCC 1.000、无卡时 0.248，阈值给 0.8 极安全。

> 换日 / 换活动后「免费」的字体或底色变了 → 重采 `image/shop/free_label.png`，
> **从模拟器原生截图裁，不要缩放**（模板必须是 720p 无损原图的裁剪）。

### 点卡身，不点文字

`target_offset: [0, -150, 0, 0]` —— 「免费」两字写在卡片**底部**，直接点文字有概率
点到卡片下沿或网格缝隙（旧版「点了没反应」就是这么来的）；往上 150px 仍落在卡身内。

### 弹窗按钮「先认出再点」，这条不能省

点完卡片到弹窗出现之间有 1~2 秒。`商店确认免费` 的作用就是**先匹配到绿色按钮才点**：
期间如果没弹出窗，盲点固定坐标会按到隔壁那张「500 金币」的卡上 —— 那是要花资源的。

### 「已收集！」不再提前收工

当天领完之后，卡片会变成灰底「已收集！」并**常驻在屏上**。
旧版用它当「今天领完了」的提前退出信号（省得白翻几十屏），
但用户要求的是「**每日免费礼物 / 维护礼物 两个都拉到底，识别不到自动跳过**」——
一旦用「已收集！」提前收工，排在更下面的「维护礼物」就永远扫不到。
所以这一版把那个节点**删掉**，改成一路扫到底，靠滑动预算兜住。

> 代价：已经领过的日子也要完整翻一遍（60 × 每屏），几十秒。
> 如果嫌慢，把「已收集！」那个节点加回 `商店扫屏.on_error` 的最前面即可 ——
> 但那样就放弃了「往下找维护礼物」。

### 「翻到底就跳过」靠 `max_hit`，不是靠猜

纯 JSON 判不出「列表真的到底了」（没有比较前后两帧的能力），所以用**次数**近似：

- `商店滑一屏` 的 `max_hit: 60` 就是滑动预算；
- 实测确认（探针）：**`max_hit` 用尽的节点，在调用方的 `next` 和 `on_error` 两个列表里都会被跳过**；
- 所以把 `商店扫到底` 排在 `商店滑一屏` 后面 —— 预算用完 → 被跳过 → 落到收工节点，**不报错**。

`max_hit 60 × 每屏下移约 720px ≈ 覆盖 45~50 屏`，够越过实测的 20+ 屏。

### ⚠️ 滑动必须慢（用户明确反馈「滑动太快 ocr 识别可能不好」）

`商店滑一屏` 的参数是三件事一起做的：

| 参数 | 值 | 作用 |
| --- | --- | --- |
| `duration` | 1200 | 慢拖，不是快甩 —— 快甩会带出惯性滚动 |
| `end_hold` | 300 | 到终点**先按住 300ms 再抬手**，彻底消掉惯性 |
| `post_delay` | 1800 | 停稳 1.8 秒后才让识别看，避免读到模糊帧 |

起点 `[360,1060]`、终点 `[360,340]`：起点在列表内、终点在页签行下沿，单次下移约 720px。

### 商店那一页非常长

实测：从顶部连翻 **30 屏**，下面全是付费项和「传奇宝箱」绿色板块 —— 所以预算必须给足，
而且**不能假设免费卡在某一屏出现**，只能一屏一屏扫。

## 三、部落：捐赠（结构同商店，**未实机验证**）

### 点一下就直接捐出，没有二次确认弹窗

所以「捐完要点确定」是**错的**：底部那个「确定」是**退出聊天**的按钮。
每捐一次就点它一下 = 捐完一次就退出，永远捐不了第二次。
⇒ 只在**全部捐完之后**点它一次（`部落退出聊天`）。

### 「捐赠」必须用白字掩码认，不能原色匹配

聊天里可能同时有「自己发起的请求」（按钮**灰的**、捐不了）和「别人的请求」
（按钮**亮绿色**、可以捐）。模板从灰按钮裁的话，绿按钮只有 **0.822**（低于 0.85 会被丢掉）；
换成白字掩码后「捐赠」两个字在任何底色上都是白的：灰按钮 **0.997** / 绿按钮 **0.898**。

### 进聊天页也要容错

聊天子页里底部导航条被输入条（请求换卡 / 友谊战…）和「确定」盖住，导航模板匹配只有 **0.00**。
所以 `部落进入聊天` 匹配不上时 `on_error` 直接接下一步、不中断：
先用 `部落点聊天入口` 点顶部聊天入口，最后再用 `部落退出聊天` 把「确定」点掉、露出导航条。

### ⚠️ 待实机确认

- `部落退出聊天` 的「确定」位置只从旧文档得知「在底部」，roi 给的是
  `[150, 1050, 420, 220]`；实测点不中就按真机位置收紧。
- `部落翻页` 的 `max_hit: 8`（对着旧的 `DONATE_LOOK_SCREENS = 8`）。
- `部落捐一个` 的 `max_hit: 1` 会被界面上的「最多捐几个请求」用 `pipeline_override` 覆盖。

## 四、怎么调

| 想改什么 | 改哪里（都是 `daily.json` 的字段） |
| --- | --- |
| 往下翻多少屏就收工 | `商店滑一屏` 的 `max_hit` |

## 五、验证状态（如实分开写）

### 已在真机验证 ✓

1. **完整路径走通**：底部商店 → 礼物盒 → 超值推荐 → 慢速下翻 → 每日精选 → 免费卡 → 弹窗 → 领取。
2. **领取真的生效**：宝石 `8 497 → 8 522`（+25），卡片随即变「已收集！」。
3. **没有「恭喜获得」二次弹窗** —— 弹窗关掉就结束了，不需要额外点。
4. **三个模板全屏 NCC = 1.000**（`free_label` / `free_confirm` / `gift_icon`），
   无目标时掉到 0.18~0.25，阈值 0.8 / 0.85 都在安全区。
5. `tools/validate.py` 全部通过（60 个节点、50 处模板引用、114 处节点引用）。

### 还没验证 ⚠️

- **流水线里「点免费卡 → 点绿色按钮」这一段的编排**：模板与坐标都是实测的，
  但今天这份免费礼物已经领掉了，没法再触发一次 → 只能等明天自然刷新时看日志。
- **「维护礼物」**：本机账号当前没有维护礼物，无法确认它的文案、位置、弹窗形态。
  现在按最保守做法实现（全列表区 OCR 认「维护」，命中才点）。
  ⚠️ 极端情况下误认会把某个报价的确认弹窗点开，那个弹窗不会被自动关掉 ——
  但商店列表里点卡**只会开确认弹窗、不会直接扣款**，所以不会真的花掉资源。
- **部落捐赠整条**（进聊天、翻页、「确定」的位置）一次都没跑过。
